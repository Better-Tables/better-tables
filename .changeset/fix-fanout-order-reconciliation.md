Fixed primary-row ordering under two-phase fan-out (one-to-many/array-FK) pagination. Since the `fix-join-pagination-underfill` fix, fetching a page across a fan-out join runs in two phases: phase 1 picks the page of primary keys (`GROUP BY` pk, ordered by aggregated `MIN`/`MAX` sort columns with a `pk asc` tiebreaker), then phase 2 fetches every joined row for exactly those keys. Phase 2 re-applied its own `ORDER BY` on the raw, non-aggregated sort columns with no primary-key tiebreaker, so the final row order (first-seen order after grouping) could disagree with phase 1's authoritative page order — most visibly under multi-column sorts, where aggregating each sort column independently is not equivalent to sorting by the tuple of columns from one row (a single page's order could differ from the same data paginated one row at a time), and in principle under sort-value ties or empty `sorting` where phase 2 had no deterministic tiebreaker at all. Phase 2's flat rows are now reordered in memory (stable, O(n)) to match phase 1's key order exactly before being grouped into nested rows; phase 2's own `ORDER BY` still determines ordering *within* a primary key's related rows (e.g. which of a user's posts comes first). No API change.
